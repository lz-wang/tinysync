# Domain Docs

工程类技能在探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- 根目录 **`CONTEXT.md`**。
- **`docs/adr/`**：阅读与你将要工作的领域相关的 ADR。

本仓库为 **single-context** 布局（根目录无 `CONTEXT-MAP.md`）：

```
/
├── CONTEXT.md
├── docs/adr/
└── internal/
```

若这些文件不存在，**静默继续**：不要提示缺失，也不要建议预先创建。`/domain-modeling` 技能会在术语或决策实际敲定时惰性创建它们。

## 使用词汇表术语

当产出命名领域概念时（issue 标题、重构提案、假设、测试名），使用 `CONTEXT.md` 定义的术语，不要漂移到词汇表明确回避的同义词。

若所需概念尚不在词汇表中，这是一个信号：要么你在发明项目不使用的语言（应重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

若产出与既有 ADR 矛盾，显式指出而非默默覆盖：

> _与 ADR-0003（统一 Web toast）矛盾，但值得重开，因为……_
