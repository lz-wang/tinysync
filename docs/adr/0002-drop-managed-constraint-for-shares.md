# 共享放弃 managed 约束

旧「发布」仅允许发布 Job 的 managed_files 记录覆盖的单个文件，目的是防止把 Job 目录里未经同步的私人文件泄露出去。共享目录与 Job 本地根使该约束无法保持：managed 记录只覆盖文件、不覆盖目录，目录内天然含 unmanaged 内容。我们决定彻底放弃该约束——共享一个目录就意味着公开整棵目录（含 unmanaged 文件）。

## Considered Options

- 公开浏览按 managed_files 过滤：隐私面最小，但会出现残缺目录树（看得见目录、文件时隐时现），语义诡异。
- 创建时固化可见文件清单（快照）：像快照不像实时目录共享，与「共享目录」的直觉相悖。

## Consequences

- 「目录里有什么就会被公开什么」的知情权与责任上移给用户；文档与 ShareDialog 文案需明示这一点。
- 公开浏览页始终隐藏点文件且不提供开关，作为最小的兜底。
- 单文件共享不再校验 managed，创建链路统一为「目标存在 + root 内 + 非 symlink」。
